# 收录与审核规则

这个市场是**公开**的：谁都能看、谁都能装，所以审核是唯一的防线。
DSH 只校验索引格式，不校验插件代码——**你审核过的内容，用户会当成可信的**。

## 硬性条件（缺一条就不收）

1. **能装**：npm 上有发布版本，`package.json` 声明了 `dsh.bundle.patch`。没有这个声明，DSH 装不进去，收了也没用。
2. **开源**：源码仓库公开可访问，许可证明确（MIT / Apache-2.0 / GPL 等）。
3. **实名**：提交者是作者本人，或能证明已获作者同意。
4. **描述属实**：卡片上的标题、简介、作者、仓库链接必须和包本身对得上。
5. **没有明显恶意行为**：不窃取凭据、不静默外发数据、不在安装或启动时执行与功能无关的命令。

## 建议条件（不满足也能收，但要标 `caution`）

- 近 12 个月有更新
- 有 README 说明用法
- 依赖不多，没有奇怪的远程下载逻辑
- 有明确的卸载/清理方式

## 审核步骤（每个插件 5～10 分钟）

1. **看包**：打开 `https://www.npmjs.com/package/<包名>`，确认最新版本和发布时间。
2. **看清单**：仓库里的 `package.json`，找 `dsh` 字段：
   ```json
   "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
   ```
3. **看代码**，重点搜这几类：
   - `child_process` / `exec` / `spawn` —— 会执行命令，必须说清用途
   - `fs.` / `readFile` —— 读哪些文件？为什么？
   - `fetch(` / `http` / `WebSocket` —— 数据发到哪？
   - `credentials` / `apiKey` / `token` —— 有没有碰用户的 key
   - `postinstall` —— 安装脚本，最容易被塞东西
4. **看文档**：README 有没有夸大、有没有隐瞒权限要求。
5. **记一笔**：在 [`review-log.md`](review-log.md) 里写一行。

## 结论只有三种

| 标签 | 含义 | 什么时候用 |
| --- | --- | --- |
| `reviewed` | ✅ 已审查 | 你看完了代码，没有发现问题 |
| `new` | 🆕 新收录 | 刚进市场，还没积累使用反馈 |
| `caution` | ⚠️ 慎用 | 功能需要高权限（执行命令、读凭据、浏览器控制），或维护状况差 |

标签要诚实：`reviewed` 是对别人的安全承诺，不是装饰。

## 下架规则

出现以下任一情况，**当天**从 `plugins.txt` 删除：

- 作者要求下架
- 发现恶意代码、后门、静默数据外发
- 包被 npm 删除、弃用，或仓库转为私有
- 描述严重失实，作者拒绝更正
- 长期（12 个月以上）不维护且有已知安全问题

下架只需删 `plugins.txt` 里那一行，下次构建（6 小时内）生效。**已安装的用户不受影响**——插件在他们本地，你需要另外发公告提醒卸载。

## 复审

- 新收录：30 天后回看一次，确认没变味
- 所有插件：每半年扫一次，更新 `review-log.md` 的日期
- 有人报安全问题：立刻按「下架规则」处理，再讨论恢复

## 对用户的承诺

在 README 里写清楚三句话，别让用户误会：

1. 市场只做索引，不审计代码，装不装由你决定。
2. 插件拥有和你账号同等的权限，能读文件、联网、执行命令。
3. 发现问题的插件，请提 issue 或直接联系维护者。
